# نظام متابعة معاملات طريبيل

## v8.3 — التحكم بالطلبات
- زر **إيقاف** لكل طلب منتظر أو جارٍ، مع إشارة إلغاء حقيقية إلى الـAgent.
- زر **حذف** لكل طلب حتى لو كان قديماً أو عالقاً؛ إذا كان الـAgent ما زال ينفذه، اختفاء الطلب من السحابة يُعد إشارة إلغاء.
- زران عامان: **إيقاف الكل** و **حذف الطلبات** لتنظيف الطلبات القديمة بسرعة.
- الإلغاء يظهر كحالة مستقلة `cancelled` ولا يحول الجهاز إلى `AGENT_ERROR`.
- الـAgent يفحص أمر الإيقاف أثناء الانتظار والتنقل ويعود مباشرة لاستقبال الطلب التالي.
- تمت إضافة fallback نسبي داخل نافذة Java Security Warning الرسمية فقط، بعد التحقق من `asy.mof.gov.iq`، لتفعيل Accept ثم Run عندما لا تكشف Java 8 عناصرها بشكل صحيح.


تعديل قسم رقم الإجراء الموحد مبني على المشروع الحالي، وليس إعادة بناء.

## الحالة الحالية
نسخة v8 مرشحة للاختبار الآمن مع Hybrid Intelligent Agent؛ لم تُعتمد كنسخة Production-ready. الإنشاء الحقيقي معطل عمداً في الواجهة وAPI والـAgent إلى حين الموافقة الصريحة واستكمال التحقق الحي.

## التشغيل والفحص
- `npm ci`
- `npm test`: اختبارات عقد API مع Redis وهمي، دون ASYCUDA.
- `npm run typecheck`
- `npm run build`

Vercel يستخدم نفس متغيرات البيئة الموجودة: UPSTASH_REDIS_REST_URL وUPSTASH_REDIS_REST_TOKEN وTARABIL_AGENT_DEVICE_ID وTARABIL_AGENT_DEVICE_TOKEN وTARABIL_MOBILE_PIN. لا تضع القيم في المصدر.

زر «للتجربة» يستخدم مسار `/api/unified/test` مستقل وينشئ `test_navigation` بدون رمز شركة أو واتساب. PIN مطلوب للمصادقة فقط. حالة الجهاز تُقرأ بدون cache. تفاصيل الأخطاء الفنية تبقى محلية لأن أدوار المدير في المشروع الحالي ليست مصادقة خادمية موثوقة.

## الـAgent
راجع `local-agent/README.md` لتصميم JAB 32-bit، اختبارات الأمان، التشخيص، التشغيل التلقائي، النسخ الاحتياطية وحدود التحقق الحالي.

## حدود التحقق
تم فحص Python syntax بنجاح، وتم تمرير ملفات TypeScript الجديدة عبر parser TypeScript ولم تظهر أخطاء صياغة؛ تعذر إكمال `npm ci` في بيئة التغليف بسبب مهلة تنزيل الحزم، لذلك يجب تشغيل `npm test` و`npm run build` على جهازك أو Vercel بعد الرفع. لم يتم نشر هذه التعديلات على Vercel، ولم ينجح اختبار الهاتف إلى ASYCUDA. قيود جلسة التنفيذ منعت قراءة Credential Manager وتسجيل Task Scheduler، وتعذر اتصال JAB الحي. لا تعتبر HTTP 200 لصفحة SPA دليلاً على وجود endpoint جديد.

قبل الاعتماد: شغّل التشخيص من حساب Windows الفعلي، ثبّت مهمة التشغيل، التقط شجرة JAB الحقيقية للتحقق من محددات الشاشة، انشر النسخة المتوافقة، ثم اختبر التنقل من الهاتف من الحالات المختلفة دون إنشاء إجراء.
